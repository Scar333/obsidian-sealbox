# Восстановление файлов без Obsidian

SealBox использует открытый формат `.sealed`. Файлы можно расшифровать локально на компьютере, даже если Obsidian или плагин больше не запускается. Утилита не обращается к серверам и не изменяет зашифрованный оригинал.

## Что сохранить заранее

1. Зашифрованные файлы `.sealed`, при необходимости их `.bak`.
2. **`keyring.json` именно от этого хранилища.** Обычно он лежит в `<vault>/.obsidian/plugins/sealbox/keyring.json`. Каталог `.obsidian` скрытый; включите показ скрытых файлов. При другом каталоге конфигурации Obsidian ищите `plugins/sealbox/keyring.json` в нём.
3. Мастер-пароль **или заранее созданный ключ восстановления**. Ключ восстановления храните отдельно от vault. После смены пароля проверьте, что сохранили актуальный ключ и актуальную копию keyring.
4. Офлайн-комплект восстановления: `sealbox-decrypt.mjs`, эту инструкцию и Node.js для вашей системы.

**Ключ восстановления не заменяет `keyring.json`.** Он открывает мастер-ключ, обёрнутый внутри keyring. Без подходящего keyring обычные файлы хранилища не открыть даже при наличии пароля или ключа восстановления. Файл с собственным паролем — отдельный режим: ему нужен именно его пароль, keyring не требуется и ключ восстановления vault не подходит.

Сделайте пробное восстановление одного тестового файла сейчас: это проверит и комплект, и ваши резервные копии.

## Подготовка

Рекомендуется **Node.js 24 LTS**. Проверьте в терминале:

```sh
node --version
```

Начиная с версии 0.1.4, к релизу прилагается архив `sealbox-recovery.zip` с готовой утилитой: распакуйте его в отдельную папку. Если в вашем опубликованном релизе такого архива ещё нет, получите его из обновлённого исходного кода:

```sh
npm ci
npm run recovery:build
```

Готовый комплект появится в `dist/recovery/`. Скопируйте весь этот каталог в резервную копию. `npm ci` нужен доступ к сети; дальнейшая сборка и работа готового комплекта выполняются локально. В готовую утилиту уже включены Argon2id (WASM) и XChaCha20-Poly1305: устанавливать npm-пакеты на компьютере восстановления не нужно. Node.js всё ещё нужен.

Рядом с утилитой лежит `SHA256SUMS` для проверки, что файл не изменился при хранении. Сам по себе этот файл не подтверждает подлинность источника: сохраните комплект из доверенной копии проекта.

## Восстановление по мастер-паролю

Работайте с копиями. Создайте отдельную локальную папку вне синхронизируемого vault. Поместите в неё `sealbox-decrypt.mjs`, копию `keyring.json` и нужный `.sealed`-файл. Откройте терминал в этой папке:

```sh
node sealbox-decrypt.mjs "note.md.sealed" --keyring "keyring.json" --out "restored-note.md"
```

Введите мастер-пароль в приглашении `Password:` и нажмите Enter. Ввод скрыт, в командную строку сам пароль не добавляйте. На Windows команда та же в PowerShell; используйте кавычки для путей с пробелами.

После успешной проверки всех блоков появится `restored-note.md`. Его можно открыть любым редактором. Для PDF укажите `--out "restored.pdf"`, для изображения — соответствующее расширение. Если целевой файл уже существует, утилита откажется его перезаписывать: задайте другое имя.

## Если мастер-пароль забыт

Нужны подходящий `keyring.json` с настроенным восстановлением и сохранённый ключ восстановления:

```sh
node sealbox-decrypt.mjs "note.md.sealed" --keyring "keyring.json" --recovery --out "restored-note.md"
```

В приглашении `Recovery key:` введите ключ целиком, с дефисами или без них. Ввод скрыт. Утилита проверит контрольную сумму ключа и соответствие keyring. Она расшифровывает файл, но не сбрасывает пароль и не меняет ключи в Obsidian.

## Файл с собственным паролем

```sh
node sealbox-decrypt.mjs "private.pdf.sealed" --out "restored-private.pdf"
```

Введите собственный пароль этого файла. Утилита прочитает режим из заголовка. Аргументы `--keyring` и `--recovery` для этого случая не нужны.

## Менеджер секретов и резервные копии

`Secrets.sealed` восстанавливается той же командой. Результат — JSON с записями, логинами, паролями и полями:

```sh
node sealbox-decrypt.mjs "Secrets.sealed" --keyring "keyring.json" --out "restored-secrets.json"
```

Этот JSON можно открыть локальным текстовым редактором. Для предыдущего состояния попробуйте `Secrets.sealed.bak` и другое имя результата. Утилита читает содержимое, расширение `.bak` ей не мешает. Автоматического импорта JSON обратно в плагин эта команда не выполняет.

**Результаты восстановления больше не зашифрованы.** Не сохраняйте их в общий Git-репозиторий или синхронизируемую папку. На Linux/macOS новые файлы создаются с правами `0600`; на Windows доступ определяется правами каталога. Утилита загружает контейнер и результат в память: для крупных файлов нужен достаточный объём ОЗУ.

## Ошибки и их смысл

| Сообщение | Что проверить |
|---|---|
| `wrong master password or damaged keyring verifier` | Пароль, раскладку и правильность keyring; затем попробуйте ключ восстановления или неповреждённую резервную копию. |
| `recovery key checksum mismatch` | Опечатку в ключе восстановления. |
| `recovery key does not match this keyring` | Ключ и keyring от разных vault/версий; ключ мог быть заменён. |
| `this keyring has no recovery slot` | Восстановление в этой копии keyring не настроено; найдите более свежую копию. |
| `integrity check`, `damaged`, `truncated` | Контейнер повреждён, обрезан либо относится к другому мастер-ключу. Попробуйте исходную копию, `.bak` или историю синхронизации. Не редактируйте шифртекст вручную. |
| `helper is missing` | Вы скопировали исходный минимальный скрипт вместо собранного комплекта. Используйте файл из `dist/recovery/`. |
| `output already exists` | Выберите другое имя после `--out`. |

Справка: `node sealbox-decrypt.mjs --help`. Для автоматизации есть `--password-file` и `--recovery-key-file`; такие файлы содержат секрет в открытом виде, поэтому для обычного восстановления лучше скрытый интерактивный ввод.

Без подходящего пароля/ключа и необходимых файлов расшифровка невозможна. Восстановление не обходит шифрование и не исправляет произвольно повреждённые данные.
