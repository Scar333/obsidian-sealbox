# Публикация SealBox 0.1.4 через веб-интерфейс

В Git подготовлена версия 0.1.4. Workflow `Release` при отправке тега `0.1.4` создаёт черновик; публикация этого черновика остаётся за владельцем.

## 1. GitHub: проверить сборки

1. Откройте https://github.com/Scar333/obsidian-sealbox/actions .
2. Убедитесь, что последние запуски **CI** для обновления и **Release** для `0.1.4` завершились зелёной галочкой.
3. Если запуск красный, откройте его, затем задачу `check` или `release` и упавший шаг. Не публикуйте неполную сборку.

## 2. GitHub: опубликовать готовый черновик

1. Войдите в GitHub под владельцем `Scar333`.
2. Откройте https://github.com/Scar333/obsidian-sealbox/releases .
3. Найдите **0.1.4** с отметкой **Draft**. Откройте редактирование через значок карандаша или **Edit**.
4. Проверьте тег **0.1.4**, без `v`. Название можно оставить `0.1.4` или указать `SealBox 0.1.4`.
5. Описание уже взято из CHANGELOG; при желании отредактируйте его.
6. В Assets должны быть отдельные файлы **main.js**, **manifest.json**, **styles.css**, а также **sealbox-recovery.zip**. Автоматические архивы Source code не заменяют эти файлы.
7. Для обычного обновления выключите **Set as a pre-release**, если этот флажок включён. При наличии настройки **Set as the latest release** отметьте её.
8. Нажмите **Publish release**. Не создавайте второй релиз с тем же тегом.

## 3. Obsidian Community: обнаружить обновление

1. Откройте https://community.obsidian.md и войдите в аккаунт владельца плагина.
2. В боковом меню выберите **Plugins**, затем **Your entries → Sealbox**. Публичная карточка: https://community.obsidian.md/plugins/sealbox .
3. В меню **…** выберите **Check for new releases**.
4. Дождитесь проверки версии 0.1.4 и проверьте результаты. При необходимости используйте **Request review** для повторной проверки после исправлений.
5. Повторно добавлять плагин как новый или вводить новую версию в форму новой заявки не нужно: номер берётся из manifest и релиза GitHub.

## 4. Обновить описание и графику каталога

1. В управлении существующим Sealbox нажмите **Edit listing**.
2. Отредактируйте краткое и полное описание; исходники текста есть в `README.md` / `README.ru.md`.
3. Загрузите иконку и, если нужно, снимки интерфейса. Каталог принимает PNG/JPEG/WebP; для векторной графики сначала экспортируйте PNG. Не выдавайте схемы за снимки интерфейса.
4. Нажмите **Save**. README в GitHub и редактируемое описание каталога — отдельные места; проверьте отображение обоих.

## 5. Проверить обновление в приложении

1. Сделайте резервную копию тестового vault и его keyring.
2. Откройте **Настройки → Плагины сообщества → Проверить обновления**.
3. Установите обновление Sealbox и проверьте, что указана версия **0.1.4**.
4. Проверьте открытие старого тестового `.sealed`, редактирование и сохранение записи, блокировку и локальное восстановление тестового файла.
5. Если обновление пока не видно, сначала проверьте публикацию релиза и результат проверки каталога; обновление может появиться с задержкой.

## Чего не нужно загружать

Общая папка `/home/scar/Documents/SealBox/` содержит собранные личные материалы. В репозиторий отправляется только проект `obsidian-sealbox/`. Пользовательские `keyring.json`, пароли, recovery key, личные `.sealed` и переписка Claude не являются файлами релиза.
