# SealBox: проверка интерфейса и ошибок

Дата: 16 ноября 2026. Изменения подготовлены локально в рабочем репозитории. Проверка первоначально выполнена при версии 0.1.3; изменения затем подготовлены к выпуску 0.1.4. Публикация и обновление пользовательских vault не выполнялись.

## Что изменилось в интерфейсе

- У менеджера секретов появился отдельный заголовок. Поиск и «Создать» находятся ниже: в проверенном стенде расстояние по вертикали между нижней границей крестика и верхней границей кнопки — от 34 px.
- Поля, карточки, шаблоны и панели получили согласованные отступы. Цвета берутся из темы Obsidian, включая её акцент; стандартный фиолетовый акцент гармонирует с новым оформлением README.
- Карточки и группы стали настоящими кнопками: работают Tab, Enter и Space, есть видимый фокус и состояние выбора.
- Панель сохранения закреплена внизу формы. Удаление визуально отделено от основного действия.
- На узких экранах панели перестраиваются; длинные названия, поля и подписи кнопок переносятся без горизонтального переполнения. Минимальная высота кнопок на узких экранах — 44 px.
- При смене записи и закрытии изменённой формы требуется подтвердить отказ от сохранения. Это действует и в быстром создании.
- В настройках доступа есть локальное окно «Восстановление без Obsidian» с перечнем резервных копий и командами.

## Найденные и исправленные ошибки

| Проблема | Исправление и проверка |
|---|---|
| Менеджер секретов проглатывал ошибку записи и затем показывал «Сохранено». | Состояние меняется только после успешной записи. Стенд имитирует ошибку диска и проверяет, что текст остаётся в форме, а ложного успеха нет. |
| Повторные нажатия запускали параллельные записи; разные локальные окна могли сохранять снимки старой базы. | Обновления базы сериализованы и применяются к последней версии. На время записи поля и кнопки блокируются. Проверены двойное нажатие, параллельное добавление двух записей и повтор после ошибки. Это не распределённая блокировка между устройствами. |
| Несохранённые поля исчезали при выборе другой записи или закрытии окна. | Подтверждение отказа от изменений; проверены отмена перехода и отказ от черновика быстрого создания. |
| Расшифровка, законченная после блокировки/смены файла, могла вернуть содержимое в окно. Аналогичная гонка существовала у загрузки базы, редактора, PDF и завершения сохранения. | Поколения состояния отбрасывают устаревшие результаты; данные/обработчики освобождаются. Стенд проверяет задержанную расшифровку файла и базы с блокировкой до завершения. Ветви редактора/PDF также проверены чтением кода и компиляцией, но не отдельным полнофункциональным PDF-тестом в Obsidian. |
| Закрытие представления и его кнопка блокировки могли не дождаться сохранения. | Перед этими действиями выполняется сохранение. Системная/автоматическая блокировка по-прежнему сразу очищает открытые данные; при несохранённых правках показывается предупреждение. |
| Утилита восстановления не работала с обычным Argon2id, ключом восстановления и каскадом. Предлагала установить helper, но не использовала его. | Реализованы все эти режимы и однокомпонентная офлайн-сборка с криптографическими зависимостями внутри. Проверены контейнеры, созданные плагином, во всех сочетаниях KDF/каскада/режима ключа. |
| Утилита могла перезаписать существующий файл; не проверяла полностью заголовок, пустое тело и имя из метаданных. | Запись с `wx`, проверка структуры, безопасного имени и аутентификации всех блоков до вывода. Тесты проверяют сохранность оригинала/существующего результата, повреждение, обрезание и попытку выхода из каталога. |
| Пароль из Windows-файла получал лишний `CR`; интерактивный ввод был видимым. | Обработка BOM/CRLF и скрытый ввод. Отдельно проверен интерактивный ключ восстановления в псевдотерминале на Node 24. Приглашение выводится после отключения эха, чтобы быстрая вставка тоже не раскрывала ключ. |
| Парсер ключа восстановления принимал хвостовые символы, а keyring не ограничивал затраты KDF до запуска. | Проверяются длина и padding ключа; стоимость KDF ограничена до вычислений. Добавлены отрицательные тесты. |
| Экран показа recovery key не очищал сохранённые байты при закрытии крестиком. | Очистка перенесена в общий путь закрытия; проверена в стенде. |

## Восстановление и документация

- Главные страницы: [English](../README.md) / [Русский](../README.ru.md). Подходят для Markdown-страницы проекта на GitHub и GitLab. Существующие ссылки на релизы ведут в известный репозиторий GitHub; перенос на GitLab не выполнялся.
- Пошаговое восстановление: [RU](RECOVERY.ru.md) / [EN](RECOVERY.en.md).
- Исходное подробное техническое описание сохранено в [TECHNICAL.md](TECHNICAL.md). Убраны неподтверждённые оценки времени взлома и уточнены границы отзыва старых ключей.
- Сборка комплекта: `npm run recovery:build` → `dist/recovery/`. В workflow следующего релиза добавлена упаковка `sealbox-recovery.zip` и его аттестация; сам workflow в GitHub не запускался.
- Подготовленная локальная сборка плагина: `dist/sealbox-preview.zip`. Это сборка для проверки, не новый опубликованный релиз.

Особенно важно: ключ восстановления **не заменяет keyring**. Старый keyring вместе с действовавшим для него паролем/ключом всё ещё открывает тот же мастер-ключ; смена пароля не отзывает украденные офлайн-копии. Для обычного восстановления храните подходящий keyring, зашифрованные файлы и актуальный пароль либо настроенный ключ восстановления.

## Проверка и её границы

`npm run check`: проверка типов, **109 тестов**, production-сборка, проверка ограничений на сетевые вызовы и логирование. Межоперационные тесты включают сборку отдельного инструмента в временном каталоге без `node_modules` и восстановление с Argon2id + каскадом + recovery key.

`tools/review-ui.mjs`: реальные компоненты плагина в Chromium с `app.css` установленного Obsidian и небольшим адаптером модального окна. Проверены светлая/тёмная темы, ширины 320/390/760/1440 px, отсутствие горизонтального переполнения списка и мобильной формы, клавиатурная навигация и сценарии из таблицы. Скриншоты и машинный отчёт: `dist/ui-review/`.

Запуск стенда с установленными Playwright/Chromium:

```sh
node tools/review-ui.mjs --playwright /path/to/playwright-core/index.mjs --browser /path/to/chromium
```

Для CSS другой установки задайте `SEALBOX_OBSIDIAN_CSS=/path/to/app.css`; по умолчанию стенд читает его из `/usr/lib/obsidian/obsidian.asar`.

Это проверка кода и компонентов, а не независимый аудит криптографии и не тест на физическом Android. Не проверены все сторонние темы/CSS snippets и интеграции реального Obsidian с оконным менеджером и синхронизацией. Шифрование не устраняет конфликты одновременного редактирования на разных устройствах. Перед обновлением рабочего vault сделайте резервную копию и сначала проверьте сборку на тестовом хранилище.
